# OpenFOAM DrivAer Fastback Case on `wm2`

This document describes how to run and post-process the OpenFOAM-12 `drivaerFastback` tutorial case on the `wm2` cluster.


## 1. Load OpenFOAM on `wm2`

OpenFOAM-12 is already installed on `wm2`. Load the module with:

```bash
module load OpenFoam/12-openmpi4.1.5-gcc12.2.0
```

Check that OpenFOAM is available:
```bash
echo $WM_PROJECT_VERSION
which foamRun
which snappyHexMesh
which foamToVTK
```

The expected OpenFOAM version is:
```bash
12
```

## 2. Setup DrivAer Fastback Case

The setup version is on GitHub. Nothing needs to be modified.

The OpenFOAM tutorial case is located at: `/lustre/hpc/soft/OpenFoam/OpenFOAM-12/tutorials/incompressibleFluid/drivaerFastback`
In general, first copy it and mod the 
```bash
cp -r /lustre/hpc/soft/OpenFoam/OpenFOAM-12/tutorials/incompressibleFluid/drivaerFastback .
cd drivaerFastback
```

Some OpenFOAM tutorial dictionaries are provided as `.orig` files. Rename them by removing the `.orig` extension:
```bash
mv  system/snappyHexMeshDict.orig      system/snappyHexMeshDict
mv  system/controlDict.orig            system/controlDict
mv  system/decomposeParDict.orig       system/decomposeParDict
```

And create the postprocess file `system/controlDict.post` for pressure coefficient `Cp` and wall shear stress `wallShearStress`



## 3. Run the Simulation

### 3.1 Case Directory Structure

The main OpenFOAM directories are:
`system/`: Contains files that control the simulation procedure (time, numerics, parallel execution).
`constant/`: Holds static data like the mesh, material properties, and turbulence model parameters.
`0/`: Stores the initial conditions and boundary conditions for all solution variables (e.g., velocity U, pressure p).

In this case, the geometry is stored under `constant/geometry/` and the main vehicle surface patches are:  `body`, `frontWheels`, `rearWheels`


### 3.2 Submit the job through Slurm

Submit the job in `drivaerFastback` folder using:

```bash
sbatch run_drivaer_S.sbatch
```

### 3.3 Procedure

The aforementioned submission runs the simulation with the small mesh to verify that the setup works. The procedure includes:

```bash
cd drivaerFastback
./Allrun -m S -cores 8
```

The mesh options are:

```text
S   small mesh
M   medium mesh
L   large mesh
XL  extra-large mesh
```

The case is run in parallel. The distributed results are written to:

```text
processor0/
processor1/
...
processor7/
```

For example, after the run, one may see:

```text
processor0/0
processor0/250
processor0/500
processor0/750
processor0/1000
```




## 4. Post-processing


## 4.1 Solver Output
The default solver output contains fields such as `U p k omega nut`.

Quantities such as pressure coefficient `Cp` and wall shear stress `wallShearStress`, can be generated by post-processing.

The desired post-processing outputs are:
```text
p                  pressure field
Cp                 pressure coefficient field
wallShearStress    wall shear stress vector field
```

For the full vehicle surface, use the patches:
```text
body frontWheels rearWheels
```

### 4.2 Submit the job through Slurm

Submit the job with:

```bash
sbatch postprocess_drivaer_S.sbatch
```

## 4.3 Procedure
The aforementioned submission runs the postprocess procedure: 

Source the OpenFOAM run functions:
```bash
. "$WM_PROJECT_DIR/bin/tools/RunFunctions"
```

Run post-processing to compute Cp and wall shear stress (on patch) data in parallel:
```bash
runParallel foamPostProcess -solver incompressibleFluid -dict system/controlDict.post
```

Reconstruct the mesh:
```bash
reconstructParMesh -constant
```

Reconstruct the fluid data:
```bash
reconstructPar 
```


Export vehicle surface data to VTK. To export only the vehicle surface, use `-noInternal` and exclude non-vehicle patches:
```bash
foamToVTK -useTimeName -noInternal -allPatches -excludePatches '(inlet freestream ground)' -fields "(p Cp wallShearStress)"
```
The surface VTK files contain:
```text
p
Cp
wallShearStress
```

Save the vehicle surface VTK files separately:
```bash
mv VTK/allPatches VTK_car_surface
```
This avoids accidentally overwriting them with later `foamToVTK` commands.


Export volume flow-field data to VTK.
```bash
foamToVTK -useTimeName -fields "(U p)"
```
This writes volume-field VTK files under `VTK/drivaerFastback_**.vtk`
